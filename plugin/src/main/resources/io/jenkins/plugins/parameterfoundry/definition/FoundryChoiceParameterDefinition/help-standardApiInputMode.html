How buildWithParameters decodes this parameter:

  • active-choices is unflagged single or multiple string compatibility. CLI strings remain literal (null becomes empty); standard missing fields use the independent API default, exactly one field stays literal, and zero/multiple fields reject. Form missing value becomes empty, JSON null becomes the string null, arrays comma-join and other values stringify. File payloads require Foundry File. UI and API defaults are independent; Core string values retain history, queue equality and uppercase environment aliases. Required/custom/disabled controls and tables are unavailable. Reactive definitions require a shared Provider and a reviewed literal API default. Multiple compatibility requires string environment export and non-empty option values. Supplied snapshots remain validated. One empty inline option may remain selectable and submits an empty string; typed empty selects that option while typed null clears selection. Ordinary modes reject empty options; typed explicit inputs retain membership validation.
  • repeated expects one field per value.
  • For static single choices, extended-choice filters/trims CLI comma fields and repeated standard fields, then joins supported values using the delimiter into one scalar. Omission uses the legacy literal default independently of dropdown selection. Form strings remain literal and arrays join without membership filtering; other form scalar/object values become an empty string. Providers, dependencies, required and custom-value controls are unavailable. Typed omission uses the same default; explicit typed strings retain strict membership validation.
  • list-git-branches is for migrated Provider-backed single choices without dependencies. CLI non-empty strings and a nonblank first standard request field are accepted literally, including revisions absent from the dropdown. A blank first standard field or empty CLI value uses the configured default. Form JSON joins arrays with commas and uses the stored default literal when the result is empty. Only an omitted first-option default needs Git resolution. Explicit submissions do not create Provider provenance; supplied snapshots are still checked for binding and expiry. This mode disables required and custom-value controls. Typed API accepts strings or null; null clears the value and omission uses the default.
  • The compatibility browser form submits literal Git values without a snapshot token, matching the source's independent list and input behavior. Use Provider cacheTtlSeconds=0 when each page must list current refs. API clients that explicitly supply a snapshot still require a valid token.
  • json-array expects exactly one field holding a JSON array of strings.
  • delimited splits a single field on the delimiter below.
  • extended-choice supports a subset of static Extended Choice multiple-selection transports: standard requests use repeated fields, trim values and ignore unavailable choices; CLI splits on commas; legacy form JSON retains a string literally or joins array elements with the delimiter, including unavailable values, empty elements and non-string array elements. Missing/null and other scalar/object values become an existing empty string. Use submitted environment export order and duplicate deduplication; canonical values remain a set while repeated submitted values can remain in the exported string. This mode requires submitted order and delimited or disabled environment export. Ordinary and typed explicit inputs retain strict validation; verify source behavior before migrating a Job. Canonical constraints apply to the supported values in a literal. Providers and tables cannot use this compatibility mode. An empty configured option list is supported for multiple selection: omitted and comma-only CLI input use the literal default; with legacyEmptyOptionsOmitCli enabled, explicit CLI text (including an empty string) returns no parameter after canonical constraints are checked. Without that flag it returns an existing empty-string parameter, matching a nonblank comma-only source configuration. Form JSON continues to preserve its literal independently of membership. Identical duplicate inline options are supported for lists and checkboxes with selected display none, canonical duplicate deduplication and custom values disabled. Entries retain independent selection and repeated submitted values. Conflicting metadata and disabled duplicate entries remain invalid.

The Jenkins CLI accepts a JSON array in the other multiple-selection modes. Compatibility mode matches the source CLI's comma-separated input. The typed API always sends a JSON array.
