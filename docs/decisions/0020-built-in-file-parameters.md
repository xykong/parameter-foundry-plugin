# ADR 0020: Built-in File Parameters

- Status: Accepted
- Date: October 9, 2026
- Supersedes: ADR 0015

## Context

The product now requires the upload capabilities of File Parameters within
Parameter Foundry itself. Keeping that source plugin for every new upload Job
no longer satisfies the installation and replacement requirement.

## Decision

Ship a first-party file companion inside the single HPI (ADR 0016), isolated
under `companion.file`. It owns binary ingestion and retention; choices, Forms,
and Providers never interpret upload bytes as option values or controller paths.

- `foundryFile` is the unified entry: workspace, Base64 or stash delivery.
- `maxUploadBytes=0` inherits 1 MiB for Base64 or 100 MiB for stored modes; a
  positive byte limit overrides the default. The same policy applies to UI, REST,
  CLI, downstream delivery and retained-upload Rebuild.
- `foundryBase64File`: compatible Base64 entry; environment value is Base64.
- `foundryStashedFile`: compatible streamed-content entry; stash and contained file
  retain the parameter name. `<name>_FILENAME` contains only the upload basename.
- `withFoundryFileParameter`: binds Base64/stash into a unique temporary directory
  on the selected agent and removes it when the wrapper exits, including failure.
- Workspace delivery preserves Core relative destinations and original filename
  environment keys. Freestyle places automatically; Pipeline uses the wrapper
  after allocating its workspace. Ordinary targets are atomically replaced;
  traversal, drive/stream syntax, reserved device names and symlinks fail closed.
  Missing uploads leave existing workspace files untouched, matching Core.
- UI and standard Jenkins multipart API ingestion share the same bounded service.
  CLI stdin and Base64 inputs use the same validation. No input accepts a local
  controller path, archive extraction, executable upload, or automatic MIME trust.
- Stashed upload IDs are UUIDs generated by the plugin. Pending data lives only
  under the plugin's upload directory. Cancelled queued uploads are deleted.
  Build-owned copies follow build retention and support Rebuild while retained.
- Downloads require Job read permission and use attachment/octet-stream headers.
  Jenkins supplies authentication, CSRF protection, and build scheduling permissions.
- Typed JSON continues rejecting binary definitions with HTTP 409. Multipart is
  the upload transport; a JSON string never substitutes for a Stashed File.
- The companion derives its binary transport implementation from the MIT-licensed
  File Parameters plugin, with its license notices preserved and attribution in
  `THIRD-PARTY-NOTICES.md`. It has no dependency on the source plugin.

## Migration and compatibility

File Parameters definitions become class B migrations into Foundry file types.
Owners accept limits, change `withFileParameter` wrappers to
`withFoundryFileParameter`, and verify upload bytes, stash names, agent reads,
missing-file handling, and Rebuild. `unstash` calls retain their existing name.
Generated Pipelines require a reviewed Jenkinsfile change, as with other families.
File simulations remain `NEEDS_MANUAL_CHECK`: option-value replay cannot prove
binary equivalence. Historical source values are never retyped or rewritten. Rebuilding a legacy
build against a migrated Job requires a fresh upload rather than Foundry reuse.
Keep the old plugin while historical, queued/running or generated definitions
still require its classes. Core File definitions now have class B workspace-mode targets preserving their
relative destination, parameter identity and original filename environment key.
Legacy binary bytes are not converted automatically.

## Limits

Base64 is for small content and can expose its value in build environment or
parameter metadata, so it is unsuitable for secrets. Stashed content is retained
with the build and accessible to authorized Job readers; use ordinary Jenkins
retention controls. Uploads are not malware-scanned or unpacked. Global controller
multipart limits may reject a request before plugin validation.
