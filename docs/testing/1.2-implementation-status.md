# `1.2` Reactive Dependency and Snapshot Foundation

Date: August 28, 2026

## Implemented Platform

- Explicit `dependsOn` declarations and server-side dependency-graph validation.
- Cycle, self-reference, duplicate, missing, and undeclared dependency rejection.
- Dependency-bound Provider cache keys and REST query parameters.
- Opaque high-entropy `BUILD_VALUE` and `DIAGNOSTIC` snapshot audiences.
- Job, definition, Provider/Profile digest, dependency digest, and audience binding.
- Browser and Typed API snapshot submission with `fresh-or-resolve` expiry behavior.
- Build-record snapshot provenance without credentials or complete Provider responses.
- Reactive browser debounce, request cancellation, response versions, and stale-response rejection.
- Explicit loading, empty, error, stale, and last-known-good fallback states.
- Dynamic migration Provider/Cascade skeletons and verification fixtures,
  including mode-specific Active Choices Dynamic Reference semantics.

The current implementation covers common cascade behavior through declared
dependencies and dependency-bound Providers. It does not claim a separate
arbitrary tree widget or client-defined dependency language.

## Release Gates

- Core does not personalize snapshots; every endpoint still checks current Job permissions.
- Snapshot bodies remain in memory and are cleared by Jenkins restart.
- Build records contain bounded digests, timestamps, fallback state, and redacted provenance only.
- A supplied mismatched or diagnostic snapshot is rejected; an expired matching snapshot is atomically refreshed.
- REST dependency interpolation is not supported. Query values bind only through an explicit `dependencyParameter`.
