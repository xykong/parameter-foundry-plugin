# Extended Choice static transport contract

Status: baseline `0.7.288` gaps recorded below; version `0.8.296` passes the
[expanded exact-release gate](../testing/release-0.8.296-verification-2026-10-10.md).
Per-Job source/consumer/history verification remains open.

On October 10, 2026, detached synthetic definitions from Extended Choice
`388.ve7b_d0b_920e10` were compared with targets generated by Parameter Foundry
`0.7.288`. No Job was saved or scheduled. This characterizes the installed
source version, not every historical version of Extended Choice.

## Reproduction and scope

Use static `PT_SINGLE_SELECT` and `PT_MULTI_SELECT` definitions named `SAMPLE`,
with `value: 'a,b'`, `quoteValue: false`, and no scripts or property files.
For each type, compare delimiters `,` and `;` and default literals `null`, `''`,
`'  '`, `'b,a'`, `' a,unknown,a '`, and `'unknown'`.

Each configuration has 34 cases: the default factory, 11 CLI values, nine
standard-request field arrays, and 13 form JSON payloads. Include omitted,
empty, comma-only, repeated, whitespace, unknown and combined values; form
payloads also include string arrays, mixed scalar arrays, booleans, numbers and
objects. Standard-request proxies return fields only for `SAMPLE`; presence
markers and ancestor lookups return null.

Compare both whether a ParameterValue exists and the environment value it
exports. Also record the value type separately. Across 816 cases, 228 match
these two checks and 588 differ. Differences by channel are default factory
24, CLI 192, standard requests 156, and form JSON 216. These counts include
unsupported single-selection compatibility and delimiter parsing; they are not
an estimate of the proportion of real user submissions affected. The source
raised no errors in these cases. Matching environment values do not establish
Pipeline `params` type equivalence: source multiple values are strings, while
ordinary Foundry multiple values are lists.

## Observed source rules

| Entry point | Source behavior |
| --- | --- |
| Default factory | A nonblank effective default produces its exact string, including order, whitespace, duplicates and unknown values. A null, empty or whitespace-only default produces no ParameterValue. |
| CLI | Null input or a zero-length result from Java `String.split(",")` uses the default factory. Otherwise split on commas, trim fields, filter against the comma-separated option set, keep order and duplicates, then join using `multiSelectDelimiter`. |
| Standard request | Null or zero-length field arrays use the default factory. Otherwise trim and filter each field, keep order and duplicates, and join using `multiSelectDelimiter`. Combined comma fields are not expanded. |
| Form JSON string | Preserve the string literally without membership validation, splitting or trimming. Missing, null and other scalar/object values produce the empty string. |
| Form JSON array | Join elements using `multiSelectDelimiter`, without membership validation. Mixed `[42, true, null]` exports `42,true,null` with a comma delimiter. |

The CLI and standard-request rules apply to both characterized selection
types. A single-select definition can therefore export several supported
values joined into one string. The configured output delimiter does not
replace commas as the separator for the source option configuration.

Examples with options `a,b`:

| Configuration / submission | Source export | Current target behavior |
| --- | --- | --- |
| Multiple, default `b,a`, omitted CLI | `b,a` | Exports `a,b` |
| Multiple, default `unknown`, omitted CLI | `unknown` | Drops the literal |
| Multiple, blank default, omitted CLI | No ParameterValue | Produces an empty multiple value |
| Multiple, default `b,a`, standard fields `[]` | `b,a` | Produces an empty multiple value |
| Multiple, form string `unknown` | `unknown` | Rejects unknown value |
| Multiple, form string ` b , a ` | ` b , a ` | Rejects whitespace-bearing values |
| Multiple, delimiter `;`, CLI `b,a` | `b;a` | Drops values because the adapter parses options using `;` |
| Multiple, delimiter `;`, form string `b,a,a` | `b,a,a` | Rejects the literal |
| Multiple, delimiter `;`, form array `[b,a,a]` | `b;a;a` | Rejects the values |

## Required implementation and verification

An explicit static source compatibility path must distinguish absent input,
an existing empty value, and an exact literal. Keep source transport decoding
and value construction in shared evaluation code so CLI, HTTP, default factories
and typed omitted input cannot disagree. Canonical option sets alone cannot
represent this contract.

Preserve the exact source default separately from UI selectable defaults.
Preserve form strings and joined arrays without turning unknown literals into
new selectable options. Restrict this behavior to the explicitly selected
static compatibility mode; ordinary choices and Provider-backed validation
retain their existing contract. Review persistence, queue equality, environment
export, Pipeline consumption, Rebuild and downstream handling for literal values.
Typed explicit input has no source equivalent and needs a documented contract;
typed omitted input must use the same default factory as other entry points.

Extend tests beyond the supported-value subset in UP-AC-036. A release gate must
cover the full matrix, configuration save/reload, ordinary-mode isolation, and
real-browser selection/submission. Before migrating a Job, separately verify
its actual option set, UI defaults, parameter consumers and generating source.
The current migration classification or a matching historical sample is not
proof of all-channel equivalence.
